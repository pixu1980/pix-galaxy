# Support

## When to Open an Issue

- Use the bug report template for broken behavior, regressions or packaging problems.
- Use the feature request template for API ideas, theme additions or language support proposals.

## Before Opening an Issue

- Read README.md.
- Check existing issues.
- Reproduce on the latest version when possible.

## Security Issues

For vulnerabilities, follow SECURITY.md and avoid public disclosure before maintainers can triage the report.

## Scope of Support

The project supports the published package, documented API surface and the maintained examples in the repository. Help with unrelated application code, framework-specific integrations or custom forks may be limited.
